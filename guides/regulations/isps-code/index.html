ISPS Code: A Practical Guide for Seafarers

Quick answer

The International Ship and Port Facility Security Code (ISPS Code) is the security framework made mandatory through SOLAS Chapter XI-2. It entered into force on 1 July 2004. For crew it means an approved Ship Security Plan, a designated Ship Security Officer, three security levels, controlled access, regular drills and records, and an International Ship Security Certificate that port state control officers may verify when the ship is in port.

What the ISPS Code is and where it came from

The ISPS Code was adopted in December 2002 by a Diplomatic Conference of SOLAS Contracting Governments, alongside amendments to SOLAS. The conference created a new Chapter XI-2 (special measures to enhance maritime security) and amended Chapter XI-1. Both the Code and the SOLAS amendments entered into force on 1 July 2004.

The Code treats security as a risk-management exercise shared between three parties:

  • Governments, which set security levels and approve plans
  • Shipping companies and their ships
  • Port facilities

It does not turn merchant seafarers into armed guards. It makes sure every ship and port facility has assessed its vulnerabilities, written down how it will respond, and named the people responsible.

Who it applies to. The Code applies to ships on international voyages:

  • Passenger ships, including high-speed passenger craft
  • Cargo ships, including high-speed craft, of 500 gross tonnage and upwards
  • Mobile offshore drilling units

It also applies to the port facilities that serve those ships. Warships and government ships on non-commercial service are outside it.

Some administrations apply similar measures to domestic or smaller ships under national law. Check your flag's requirements if you sail on such a vessel.

Structure: Part A, Part B and the key people

The Code is in two parts:

Part Status Content
Part A Mandatory Requirements for governments, companies, ships and port facilities
Part B Recommendatory guidance How to meet Part A, e.g. plan contents, drill frequency, security measures at each level

Part B is guidance, but do not treat it as optional in practice. Several administrations have made parts of it mandatory under national rules, and auditors use it as the benchmark.

The key roles:

  • Company Security Officer (CSO). Ashore. Responsible for the Ship Security Assessment, getting the plan approved, and acting as the 24-hour security contact.
  • Ship Security Officer (SSO). On board and accountable to the master. Implements and maintains the plan, organises drills and inspections, keeps the records and liaises with the CSO and the Port Facility Security Officer. Which rank holds the role is a company decision. It is often the chief officer, but this varies.
  • Port Facility Security Officer (PFSO). The shore-side counterpart at each port facility.

Security levels. These are set by the Contracting Government: the flag for its ships, and the port state for its port facilities.

  • Level 1. Normal. Minimum protective measures are maintained at all times.
  • Level 2. Heightened. Additional measures apply because the risk of a security incident is increased.
  • Level 3. Exceptional. Specific further measures apply for a limited period when an incident is probable or imminent, even if the exact target is unknown.

Before entering a port, the ship must meet the security level set by that port state if it is higher than the level set by the flag.

The Code also requires the company to state clearly in the plan that the master has overriding authority to make decisions on the safety and security of the ship.

Certificates and documents the Code creates on board

Ship Security Assessment (SSA) and Ship Security Plan (SSP). The CSO, or a recognised security organisation, carries out the assessment. The plan is built on it and is approved by the Administration or by a recognised security organisation acting on its behalf.

The plan must:

  • Be in the ship's working language, with a translation into English, French or Spanish if the working language is none of these
  • Be protected from unauthorised access or disclosure

Some amendments to an approved plan need fresh approval before they are implemented.

International Ship Security Certificate (ISSC). This is issued after initial verification and is valid for up to five years. At least one intermediate verification is required. If only one is carried out, it must take place between the second and third anniversary dates.

Interim ISSC. This covers specific situations such as:

  • A ship on delivery
  • A change of flag
  • A company taking over a ship it did not previously operate

An interim certificate is valid for six months and cannot be extended. An Administration (or RSO) must not issue a subsequent, consecutive interim certificate if the purpose is to avoid full compliance with the Code.

Related SOLAS requirements that inspectors check alongside the ISSC:

  • IMO ship identification number permanently marked on the hull and internally (Chapter XI-1)
  • Continuous Synopsis Record (CSR). Issued by the flag, it gives the ship's history of flag, name, owners, managers, class and certificate issuers. Previous entries are never erased.
  • Ship Security Alert System (SSAS) (Chapter XI-2)

What it means in your daily work

Most ISPS work is routine. The detail of every measure is in your ship's SSP, so read the parts relevant to your duties during familiarisation. Typical tasks at security level 1:

  • Gangway and access control. Check identity and the reason for each visit against expected lists, log visitors, issue passes and escort where the plan requires it. Nobody comes aboard just because they are wearing a hi-vis vest.
  • Restricted areas. The bridge, engine room, steering gear room and similar spaces are locked or monitored according to the plan.
  • Stores, baggage and deliveries. Check them against orders before acceptance. Search them to the extent the plan requires at the current level.
  • Deck patrols and lighting. Watch the waterside and deck, especially at anchor and alongside at night.
  • Reporting. Report any suspicious activity, stowaway signs or breach to the officer of the watch or the SSO without delay.

At level 2 and level 3, the plan steps these measures up. Examples include:

  • Fewer access points
  • More searches
  • Extra patrols
  • Possible suspension of embarkation

Ship Security Alert System. The SSAS sends a covert alert ashore to the competent authority designated by the flag, which may include the company. The alert identifies the ship and its position. It does not sound an alarm on board or alert nearby ships.

There are at least two activation points, one of them on the bridge. Their locations are confidential. Test the system only under your company's procedure, which normally requires prior notification. Report a false activation to the CSO immediately.

Training. Under STCW, seafarers on ships covered by the ISPS Code need security-related familiarisation and, depending on role, the following certificates:

Who Requirement STCW reference
All seafarers Security awareness A-VI/6
Those with designated security duties (e.g. gangway watch, searches) Designated security duties A-VI/6
SSO SSO certificate A-VI/5

Drills, exercises and the security records you must keep

Drills. Part B recommends a security drill at least once every three months. If more than 25% of the crew has been replaced by people who have not taken part in a drill on that ship in the last three months, it recommends a drill within one week of the change.

Exercises. Part B recommends an exercise at least once each calendar year, with no more than 18 months between them. Exercises may involve the CSO, port facilities or authorities.

Check your SSP and flag circulars. Many flags treat these frequencies as mandatory.

Records required by Part A. The ship must keep records of:

  • Training, drills and exercises
  • Security threats and security incidents
  • Breaches of security
  • Changes in security level
  • Communications relating to the direct security of the ship, such as specific threats
  • Internal audits and reviews of security activities
  • Periodic review of the SSA and SSP
  • Implementation of any amendments to the plan
  • Maintenance, calibration and testing of security equipment, including SSAS tests

The retention period is set by the Administration. Records may be kept electronically if they are protected against unauthorised deletion or change.

Declaration of Security (DoS). A DoS is an agreement between the ship and a port facility, or another ship, on who carries out which security measures. Typical triggers include:

  • The ship is operating at a higher security level than the port facility or other ship it is interfacing with
  • A ship-to-ship activity with a ship that is not required to have an approved SSP
  • The ship is at a port facility not required to have an approved PFSP
  • A security threat or incident has occurred
  • Contracting Governments have agreed a DoS for certain voyages or ships

Keep completed DoS forms for the period the flag specifies.

Last ten port calls. Port states may ask for the security level the ship operated at during its last ten calls at port facilities. They may also ask about any special measures taken and any ship-to-ship activity in that period. Keep this information up to date. It also appears in many pre-arrival forms.

Worked scenario: security level raised on passage

You are 2nd officer on the 0000-0400 watch, inbound to a port. The master's standing orders say the ship is at level 1. A message arrives via the company stating that the port state has set level 2 for its port facilities.

Step by step:

  1. Call the master and inform the SSO. Log the time and source of the message.
  2. The SSO confirms the change with the CSO and checks the latest pre-arrival requirements from the port or agent.
  3. Before arrival, the ship moves to level 2 because the port level is higher than the flag level. The SSO briefs the crew on the level 2 measures in the SSP, such as:
    • A single access point
    • Extra deck rounds
    • Increased searches of stores
    • Escorting all visitors
  4. The ship acknowledges the level change to the port facility or authority as the SSP and local procedures require.
  5. The SSO records the change in security level, the communications and the measures taken.
  6. If the ship and port facility cannot agree on measures, or other DoS triggers apply, the SSO raises a Declaration of Security with the PFSO.

The common mistake is to increase the measures but forget the paperwork. The PSC officer at the next port may well ask to see the record of the level change.

What port state control typically checks

Under SOLAS Chapter XI-2, an officer authorised by the port state can verify that the ship holds a valid ISSC or interim ISSC. If there are clear grounds to believe the ship is not compliant, the officer can take control measures:

  • Inspection
  • Delay
  • Detention
  • Restriction of operations
  • Expulsion from port

Typical checks:

  • ISSC validity and endorsement of the intermediate verification
  • CSR up to date and matching the ship's current details
  • IMO number markings
  • Gangway control in practice: whether the inspector was challenged and asked for ID
  • Security awareness and designated-duties certificates for the crew
  • SSO certificate and whether the SSO knows the plan
  • Drill and exercise records
  • SSAS test records
  • Last ten port calls information
  • Records of security level changes

SSP confidentiality. The SSP is not routinely open to inspectors. With clear grounds, limited parts may be examined. Certain sections are treated as confidential and cannot be inspected without the consent of the flag state. These include those covering restricted areas, response to threats and the SSAS activation points.

If an inspector asks for the full plan, the master or SSO should politely explain this and contact the CSO and flag if needed. Do not refuse cooperation generally.

Unanswered questions at the gangway, or an unattended gangway, are among the commonest triggers for a closer ISPS inspection.

Oral exam: questions examiners like to ask

  • Q: When did the ISPS Code enter into force and through which convention? A: 1 July 2004, through SOLAS Chapter XI-2.
  • Q: Which part is mandatory? A: Part A. Part B is guidance, though some flags make parts of it mandatory.
  • Q: Who approves the SSP? A: The Administration, or a recognised security organisation acting on its behalf.
  • Q: Validity of the ISSC and the interim ISSC? A: The ISSC is valid for up to five years with at least one intermediate verification. The interim ISSC is valid for six months and cannot be extended.
  • Q: What does the SSAS do? A: It sends a covert alert ashore identifying the ship and its position, with no alarm on board. There are at least two activation points, one on the bridge.
  • Q: When would you request a Declaration of Security? A: Examples include when the ship is at a higher level than the port facility, during a ship-to-ship activity with a ship that has no approved plan, after a security incident, or when the other party has no approved plan.
  • Q: Can a PSC officer read the whole SSP? A: No. Only limited parts, and only on clear grounds. The confidential sections need the flag's consent.
Key points
  • The ISPS Code is mandatory through SOLAS Chapter XI-2 and entered into force on 1 July 2004.
  • Part A is mandatory; Part B is guidance that many flags and auditors treat as the standard.
  • There are three security levels: 1 normal, 2 heightened, 3 exceptional. The ship must meet a higher port-state level before entering port.
  • The ISSC is valid for up to five years with an intermediate verification; the interim ISSC lasts six months and cannot be extended.
  • The SSAS is a covert ship-to-shore alert with no on-board alarm. Its activation points are confidential.
  • Keep records of drills, level changes, incidents, breaches, SSAS tests and the last ten port calls.
  • PSC can verify the ISSC and act on clear grounds, but confidential SSP sections need flag consent.

Frequently asked questions

Does the ISPS Code apply to my ship?

It applies to passenger ships, including high-speed passenger craft, cargo ships of 500 GT and upwards, and mobile offshore drilling units, all on international voyages. Warships and government non-commercial ships are excluded. Some flags apply similar national rules to smaller or domestic ships, so check your flag's requirements.

Who can be the Ship Security Officer?

The company designates the SSO for each ship, and that person must hold an SSO certificate meeting STCW Section A-VI/5. On many ships it is the chief officer, but the rank chosen is a company decision and practice varies between companies and flags.

How often must security drills be held?

Part B of the Code recommends a drill at least every three months. It also recommends an extra drill within one week if more than 25% of the crew has changed with people who have not drilled on that ship in the last three months. Exercises are recommended at least once per calendar year, no more than 18 months apart. Many flags make these frequencies mandatory, so follow your SSP.

What should I do if the SSAS is activated by mistake?

Tell the master and SSO at once. Follow the SSP procedure, which normally means informing the CSO and the competent authority without delay so that no response is launched. Record the event as the plan requires.

Can a port state control officer demand to see the whole Ship Security Plan?

No. Inspectors verify the ISSC and, where there are clear grounds, may examine limited parts of the plan. Sections the Code treats as confidential cannot be inspected without the consent of the flag state. The master should cooperate and involve the CSO and flag if pressed.

Test yourself

How long is an interim International Ship Security Certificate valid?

An interim ISSC is valid for six months and cannot be extended, and an Administration must not issue consecutive interims to avoid full compliance. Reference: ISPS Code, Part A, Section 19.4.

Which part of the ISPS Code is mandatory?

Part A is mandatory under SOLAS Chapter XI-2. Part B is recommendatory guidance, although some administrations make parts of it mandatory. Reference: SOLAS Chapter XI-2; ISPS Code Parts A and B.

When the Ship Security Alert System is activated, what happens?

The SSAS sends a covert ship-to-shore alert to the competent authority designated by the Administration, which may include the company. It does not raise an alarm on board or alert other ships. Reference: SOLAS Chapter XI-2, Regulation 6.

Security level 3 means:

Level 3 is the exceptional level, when an incident is probable or imminent, even where the specific target cannot be identified. Reference: ISPS Code, Part A, Section 2.

A port state may ask for security information covering how many previous port facility calls?

Ships may be required to provide the security level and any special measures for their last ten calls at port facilities. Reference: SOLAS Chapter XI-2, Regulation 9.
